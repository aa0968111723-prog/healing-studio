| **AIDV-836** | Medium | opt-card, frontend, uiux, auto-pass | `client/src/components/OnboardingFlow.tsx:269-273` `handleBranchNavigate` 先呼叫 `onComplete()`（Home.tsx prop：`setShowOnboarding(false)` + `navigate("/agent")`），再呼叫 `setLocation(path)`，兩次 pushState 在同一同步 call stack 內執行，歷史堆疊為 `/ → /agent → <destination>`；使用者按 Back 會落在 `/agent`（非預期）。今日 AIDV-810 新增 branch chips 時引入。修法：`onComplete` 不再 navigate，改由 `handleBranchNavigate` 單一呼叫 `setLocation(path)` 並傳 `{ replace: true }` 清除多餘 entry。 |
| **AIDV-837** | Medium | opt-card, frontend, error-handling, auto-pass | `client/src/shells/AidvShellChrome.tsx:53-62` `prefsQ.isError` 無處理分支——`getPreferences` API 回傳錯誤時 `prefsQ.data` 為 undefined，`useEffect` 條件 `prefsQ.data && !prefsQ.data.onboardingCompletedAt` 永不成立，OrbOnboarding 對話永不開啟；新使用者在 API 故障時永遠見不到冷啟動流程。今日 AIDV-830 新增此查詢時未加錯誤分支。修法：在 `useEffect` 加 `else if (prefsQ.isError)` 分支，顯示輕量 error banner 或 fallback 開啟對話框（Bruce 決策 fallback 行為）。 |
| **AIDV-838** | Low | opt-card, frontend, uiux, auto-pass | `client/src/components/orb-agent/OrbOnboardingDialog.tsx` `updateMutation.onSuccess` 無條件呼叫 `onCompleted?.(answers)`（→ `navigate("/video")`）——若使用者在 mutation pending 期間手動關閉對話框（X/backdrop），mutation 成功後仍觸發導覽，造成意外頁面跳轉。今日 AIDV-830 新增此 mutation 時未加 dismissal guard。修法：用 `useRef` 追蹤手動關閉狀態，`onSuccess` 先查 ref 再決定是否呼叫 `onCompleted`。 |
