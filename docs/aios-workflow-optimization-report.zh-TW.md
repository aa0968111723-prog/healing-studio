# AIOS 電腦版專案工作流優化報告

**測試日期：** 2026-08-17  
**測試範圍：** 登入後 dashboard、`/planner`、實際專案頁 `/p/{uuid}`、腳本輸入、AI 解析、產生分鏡、單格工作室、Aios 助手與組內留言  
**測試專案：** API 測試暫存專案  
**執行者：** Manus AI

## 一、結論摘要

本輪不是只檢查畫面，而是使用實際登入帳號把「佛誕故事腳本 → AI 解析 → 分鏡 → 單格生成 → 依賴修復 → Aios 助手」完整走過數次，並以完整腳本與極短控制腳本交叉測試。結果顯示，AIOS 的核心能力已經具備：腳本可以產生角色、場景、道具與分鏡，分鏡可以進入單格工作室，模型、點數與變體方向也有一定可觀測性。然而，桌面版目前最大的問題不是功能數量不足，而是**狀態來源分散、主流程不夠集中、生成前依賴無法修復，以及不同 AI 入口的功能邊界不清楚**。

最需要優先處理的是三個 P0 問題。第一，AI 解析長時間停留在「解析中…」時，沒有進度、取消、timeout、錯誤原因或重試；在其中一次測試中，原本 130 字腳本在畫面上縮成「難陀」兩個字，重新載入後更完全遺失。第二，生成畫面因「清淨水」的主人不在該鏡而失敗，但錯誤沒有提供一鍵修復、差異預覽或直接前往受影響欄位的路徑。第三，專案頁中的「告訴 Aios 修改目前分鏡」、「問 AI 助手」與「組內留言」容易被視為同一個入口；實測送出 `@助手` 後只留下留言，沒有建立可追蹤的工作任務。

## 二、實測工作流與結果

| 測試階段 | 實際操作 | 結果 | 產品判斷 |
|---|---|---|---|
| 腳本輸入 | 貼入完整佛誕故事與兩項畫面說明 | 顯示 130 字、2 段，但下一步仍顯示「先寫故事」 | 輸入完成後缺少明確 ready 狀態 |
| AI 解析 | 完整腳本點擊「AI 解析」 | 長時間停留解析中，無進度或重試；畫面曾縮成 2 字 | 高風險資料同步／請求競態 |
| 控制測試 | 以 42 字短腳本重試 | 短稿同樣長時間無回應 | 問題不只是長度或 token |
| 建立分鏡 | 點擊「產生分鏡」 | 後端可建立 2 場、3 鏡，但前端仍殘留舊狀態 | 解析、分鏡與 UI 狀態來源不一致 |
| 分鏡拆解 | 故事與畫面說明同時存在 | 產生未分場殘留鏡頭，使用者需手動判斷刪除 | 需要拆鏡摘要與重複鏡頭合併建議 |
| 單格工作室 | 進入第 3 鏡並擴寫提示詞 | 能儲存提示詞並進入模型選擇，但缺少自動提示詞中間層 | 需要從鏡頭描述自動生成製作級 prompt |
| 重畫生成 | 選擇 FLUX.1 [schnell]、約 1 點 | 因道具主人校驗失敗，沒有產出 | 依賴檢查應在扣點前阻擋並提供修復 |
| 選鏡同步 | 失敗後選取第 3 鏡 | 上方 Aios 命令列仍顯示 Shot 01 | 高優先級選取狀態不同步 |
| 修復指令 | 要求將清淨水綁到難陀龍王 | Aios 路由成影片生成與老照片修復推薦 | 意圖分類缺少「資料關聯修復」路由 |
| 助手入口 | 點擊「問 AI 助手」並送出 `@助手` | 只留下組內留言，未產生可執行任務 | 文案與行為不一致 |

## 三、桌面版資訊架構建議

桌面專案頁不應把所有能力平鋪在首屏。建議以「**目前專案狀態 → 下一步 → 工作區 → 協作與脈絡**」作為固定層級。首屏只需要回答三個問題：目前在做哪個專案、現在完成到哪裡、下一個最重要的動作是什麼。

| 桌面區域 | 建議承擔的責任 | 不應放置的內容 |
|---|---|---|
| 專案 Header | 專案名稱、同步狀態、畫幅、目前階段、主要下一步 | 重複的專案設定入口 |
| 進度帶 | 故事、解析、分鏡、畫面、影片、交付的完成度 | 細部素材編輯控制 |
| 主工作區 | 故事輸入、解析、分鏡編輯或單格生成其中一個主工作 | 全部工具同時展開 |
| 右側工作台 | 專案進度、阻擋項目、下一步、組內留言、專案脈絡 | 讓留言看起來像可執行 AI 任務 |
| 更多工具 | 角色、場景、道具、造型、對白、旁白、轉場、註記 | 與主 CTA 同層競爭注意力 |

`/planner` 應維持筆記、排程與知識地圖的角色，但要提供「聚焦目前專案」與「回到專案工作區」的清楚入口。它不應被誤當成專案詳情頁；專案頁則應能反向查看該專案的排程、筆記與知識脈絡。[1]

## 五、建議優先級

| 優先級 | 問題 | 建議解法 | 驗收標準 |
|---|---|---|---|
| P0 | AI 解析無限等待、內容可能被截斷 | 保存請求內容快照；加入 30–60 秒 timeout、取消、重試、錯誤碼與解析進度 | 任何解析都能看到狀態；失敗不遺失原稿；可一鍵重試 |
| P0 | 生成前道具／角色依賴不可修復 | 生成前跑 dependency preflight；列出受影響鏡頭、欄位與修復差異 | 使用者可在扣點前修復、略過或回到設定；修復可復原 |
| P0 | `@助手` 留言沒有工作任務結果 | 將「問 AI 助手」改成真正的任務面板，留言功能改名為「@助手留言」 | 送出後有任務卡、狀態、執行／略過／結果與錯誤 |
| P1 | 分鏡修正命令列與專案助手混淆 | 元件與文案分成「修改目前 Shot」和「詢問／規劃整個專案」 | 兩個輸入框的標題、placeholder、快捷提示與結果區完全不同 |
| P1 | 選取第 3 鏡但命令列仍指向 Shot 01 | 以 selected shot id 作單一資料來源，所有命令列、面板與生成請求都顯示同一 id | 切換鏡頭後上下文同步更新；測試可驗證送出目標 |
| P1 | 自動拆鏡產生重複或未分場鏡頭 | 建立拆鏡摘要、合併相似鏡頭與「保留／合併／刪除」確認 | 產生分鏡後不再默默留下重複鏡頭 |
| P2 | 模型選單把圖片、影片、成本與速度混在一起 | 依輸出類型、用途、成本與速度分組；顯示預期結果與點數 | 使用者能在一次選擇中理解模型用途與成本 |
| P2 | `/planner` 與專案頁脈絡斷裂 | 專案頁提供聚焦到目前專案的 planner 入口；planner 提供回到專案工作區 | 兩邊可互相保留專案 context |

## 七、下一輪最值得做的實作

下一輪應先做一個可驗收的「生成前檢查抽屜」。當使用者按下「生成畫面」時，系統先顯示該鏡頭的角色、造型、場景、道具與 owner 關係；若發現清淨水主人不在鏡頭中，直接提供「加入難陀龍王」「改由優波難陀龍王持有」「移除道具依賴」三個選項，並在送出前顯示差異預覽。這會比單純再增加一個 AI 推薦模型更能解除目前真正的生產阻塞。

接著應把腳本輸入、AI 解析與分鏡建立串成一條有狀態的 workflow stepper：`草稿已保存 → 正在解析 → 解析完成 → 待確認依賴 → 可建立分鏡 → 可生成畫面`。每一階段只提供當下真正可做的主行動，其他功能收進次要工具列。這將同時改善新使用者理解、桌面版視覺噪音、生成點數風險與動畫組大量試作時的恢復效率。
