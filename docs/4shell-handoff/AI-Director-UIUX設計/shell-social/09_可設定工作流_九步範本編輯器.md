# 09 · 可設定工作流 — 九步＝預設範本＋工作流編輯器

> 把 `/social` 的九步從**固定流程**升級為**預設範本（default template）**：使用者可**新增／刪除／重排／啟用停用／改名**步驟、設**必經/可選**、存成**自訂範本**、**重設回預設**，以因應不同設計案。
> **與 `/video` 一致**：兩條創作線共用設計系統**即將提供的「可設定工作流」元件家族**（`WorkflowEditor`/`StepCard`/`StepLibrary`/`WorkflowBar`）。本檔先定**消費端 props 契約**，元件落檔後對齊；**不在 `/social` 另造**。
> 鐵律：**可設定的是「引導旅程的形狀」，不是「安全閘門」**——確認門（成本/品牌/來源）與品管脊椎**永遠強制**，不因刪步而消失（見 §6）。
> 九步內容本身（每步做什麼）規格在 `02`–`06`；本檔只定**範本／步驟的元層（meta-layer）**：模型、編輯器、狀態、衝突、非線性相容、對回真實資料（無對應者標**「待補（屬資料模型，歸後端）」**）。

---

## 1. 概念：固定流程 → 預設範本

```
舊：S1─S2─S3─S4─S5─S6─S7─S8─S9（寫死、不可改）
新：WorkflowTemplate「九步預設」= 有序、可編輯的步驟清單
      ├ 使用者可：＋加步驟（從步驟庫） · −刪步驟 · ⇅重排 · ✎改名 · ◉啟用/停用 · ★必經/可選
      ├ 存成自訂範本（如「快速貼文 3 步」「活動海報 7 步」「品牌系列 9 步」）
      └ 重設回預設九步
```

**為什麼**：不同設計案需要不同流程——
- **快速一張圖**：只要 S1→S4→S9（停用 brief/素材/合成/外部/修正）。
- **完整活動海報**：九步全開。
- **純外部精修**：S1→S4→S7→S9（停用 S5/S6）。
- **懶人包系列**：S1→S2→S4→S6→S9（多頁卡，停用外部）。

範本決定**引導列（WorkflowBar）顯示哪些步、推薦順序、哪些必經**；**不改**每步的內部規格與安全閘門。

## 2. 資料模型（meta-layer）

> ⚠ **此節整體無現成 procedure/table → 標「待補（屬資料模型，歸後端）」**。下方為前端消費所需的形狀契約與**落地建議**；真實落表由後端在資料模型階段補。**有明確先例**：平台既有 `director.templates`／`saveSession`／`listSessions`／`loadSession`／`deleteSession`（director 33 procedure 內）已是「具名會話/範本持久化」的同型樣板，工作流範本**比照其形狀**落地即可。

```
WorkflowTemplate {                          // 【待補：table workflow_templates】
  id, name,
  scope: 'default' | 'user' | 'project' | 'team',
  isDefault: bool,                          // 預設九步＝true、唯讀（不可改不可刪，只能「複製為自訂」）
  version, createdAt, updatedAt, deletedAt   // 軟刪
  steps: WorkflowStep[]                      // 有序
}

WorkflowStep {                              // 【待補：steps JSON 或 table workflow_template_steps】
  id,
  stepKey,        // 'designType'|'brief'|'collect'|'create'|'edit'|'compose'|'external'|'revise'|'complete' | 'custom:*'
  label,          // 可改名顯示字（預設取 i18n）
  order,          // 重排序位
  enabled: bool,  // 啟用/停用（停用＝引導列不顯示、next 略過）
  required: bool, // 必經（true＝不可跳過其閘門、列上標★）
  removable: bool,// 是否可刪（系統結構必經步＝false，見 §6 鎖定表）
  togglable: bool,// 是否可停用（同上）
  route,          // 該步所在路由（/social · /social/studio · /social/brand · /social/publish）
  dependsOn: stepKey[],   // 硬依賴（producer 步），用於衝突檢查
  gate?: 'cost'|'brand'|'source'  // 綁定的安全閘門（閘門不隨刪步消失，見 §6）
}

ActiveWorkflowBinding {                     // 【待補】哪個專案/使用者套哪個範本
  scopeId（userId/projectId）, templateId, pinnedVersion?
}
```

**預設九步範本（`isDefault`，唯讀）的步驟屬性**（`removable`/`togglable`/`required` 見 §6 鎖定表）：

| order | stepKey | label（預設 i18n） | route | dependsOn | gate |
|---|---|---|---|---|---|
| 1 | `designType` | 了解設計類型 | `/social` | — | — |
| 2 | `brief` | 設計 brief | `/social` | designType | — |
| 3 | `collect` | 收集專案資料素材 | `/social` | — | source(上傳時) |
| 4 | `create` | 創作設計素材 | `/social/studio` | — | **cost** |
| 5 | `edit` | 素材修改 | `/social/studio` | create | cost |
| 6 | `compose` | 圖層拼接合成 | `/social/studio` | create\|edit | — |
| 7 | `external` | 接入 Canva/Adobe | `/social/studio` | create\|edit\|compose | source |
| 8 | `revise` | 反覆修正 | `/social` | create | — |
| 9 | `complete` | 完成專案（品牌鎖＋多尺寸＋發佈） | `/social/brand`＋`/social/publish` | create→approved | **brand·source·cost** |

> **自訂步驟 `custom:*`**：使用者可加「自由說明步」（如「給主管審核」「等講師確認文案」），無內建 route／gate，純提醒/檢查點（落 `project_notes_calendar` 一筆提醒亦可，待補）。

**元件對映（設計系統共用「可設定工作流」家族，即將提供 → 先定契約）**：

| 消費元件（設計系統） | 用途 | 關鍵 props（契約） |
|---|---|---|
| `WorkflowEditor` | 編輯器外殼（雙欄：步驟列＋步驟庫） | `template`、`onChange`、`onSave`、`onReset` |
| `StepCard`（`.wf-step`） | 一張可拖拉步驟卡 | `stepKey`、`label`、`enabled`、`required`、`locked`、`onToggle/onRename/onRemove` |
| `StepLibrary`（`.wf-lib`） | 可加入步驟的庫（含自訂） | `available[]`、`onAdd` |
| `WorkflowBar`（`.wf-bar`，= `StageBar` 的可設定泛化） | 執行期引導列（顯示啟用步、可點跳、標必經/完成度） | `steps[]`、`current`、`onJump` |
| `TemplateMenu` | 範本切換/新增/刪除 | `templates[]`、`active`、`onSelect/onNew/onDelete` |

> `WorkflowBar` 是 `/video` `StageBar`（`.stages`）的**可設定泛化**（N 步、可點跳、標 done/cur/todo＋★必經）。`/social` 與 `/video` 共用此家族，**只餵各自的 stepKey 集合**，不重造、不改色票（沿用 `00_設計系統` token）。

**每張 `StepCard` 的操作**：拖把 `⠿` 重排、`◉` 啟用/停用、`✎` 改名、`✕` 刪除、`★/○` 切必經/可選。系統鎖定步顯示 `🔒`（操作 disabled，見 §6）。

## 4. 全狀態（空 / 載入 / 錯誤 / 衝突 / 不可刪必經步驟）

| 狀態 | 內容 |
|---|---|
| **Empty**（無自訂範本） | 範本選單只有「九步預設」（唯讀）；編輯器頂部一句「這是預設九步 · 複製成自訂範本就能改」＋主 CTA「從預設建立自訂範本」。步驟庫顯示「目前九步都在使用中，停用的步會出現在這裡可重新加入」。 |
| **Loading** | 範本清單 `Skeleton`；編輯器步驟列 skeleton。套用範本切換時 `WorkflowBar` 先出灰步骨架。 |
| **Error** | 存/載/刪範本失敗 → 編輯器內操作級提示「儲存範本時出了點問題，你的調整已保留」＋重試（**不丟未存編輯**，暫存本地）。後端無對應 procedure 時走 mock：本地暫存＋標「範本持久化待後端」。 |
| **Conflict（衝突）** | 見 §5 衝突規則。衝突以**行內紅條＋受影響步高亮**呈現，並給「如何解」：①依賴倒置（消費步排在生產步前）②刪/停用被下游依賴的步 ③重複 canonical 步 ④範本改名撞名。**有未解衝突時「套用」disabled**，但可「另存草稿範本」。 |
| **不可刪/不可停用的必經步驟** | §6 鎖定步顯示 `🔒`＋★；`✕`刪除/`◉`停用 disabled；hover/長按出 tooltip 說明「**這是安全必經步，不能移除（{原因}）**」。試圖拖到非法位置時吸附回合法區。 |
| **長內容** | 步驟多（含多個自訂步）→ 步驟列虛擬滾動；範本多 → `TemplateMenu` 搜尋/分組（我的/團隊/預設）。 |
| **權限** | 範本 scope：`user` 自己可改；`project`/`team` 範本需擁有者/管理者（非擁有者唯讀＋「複製為我的範本」）；預設範本人人唯讀。 |

## 5. 衝突規則（編輯器即時校驗）

| # | 衝突 | 偵測 | UI 行為 |
|---|---|---|---|
| C1 | **依賴倒置**：消費步排在其 `dependsOn` 生產步之前（如 `compose`/`exportSizes` 在 `create` 之前；`revise` 在 `create` 之前） | 重排時即時檢查 `order(dep) < order(step)` | 紅條「『圖層合成』需要先有『創作設計素材』的產物」＋一鍵「自動修正順序」 |
| C2 | **停用被下游依賴的步** | 停用 `create` 但 `edit/compose/revise/complete` 仍啟用 | 警告「停用『創作』會讓 {N} 個下游步缺料」→ 選「一併停用下游」或「取消」 |
| C3 | **刪除被依賴的步** | 同 C2，刪除版 | 同 C2，blocked 直到下游處理 |
| C4 | **移除/停用必經步** | 目標 `removable=false`/`togglable=false` | 直接 disabled（§6），不進入衝突流 |
| C5 | **重複 canonical 步** | 同一 `stepKey`（非 `custom:*`）出現兩次 | 「每個內建步驟只能有一個」；自訂步可重複 |
| C6 | **範本撞名** | `name` 與既有同 scope 範本重複 | 存檔時提示改名或覆寫 |
| C7 | **空範本 / 無生產步** | 範本停到沒有任何會產出素材的步（無 `create`/`external` 導入） | 「這個範本不會產出任何素材，至少保留『創作』或『外部導入』」 |

> **自動修正**：C1 提供「自動依依賴拓撲排序」；C2/C3 提供「一併處理下游」。所有自動修正可復原（undo）。

## 6. 安全鎖定：哪些步不可刪/不可停用（與閘門解耦）

**核心原則**：**閘門（gate）≠ 步驟（step）**。確認門（成本/品牌/來源）是**品管脊椎**，由動作觸發、**不隨步驟刪除而消失**。編輯器只配置「引導旅程的形狀」。

| stepKey | removable | togglable | required | 原因 |
|---|---|---|---|---|
| `designType` | ❌ 不可刪 | ❌ 不可停用 | ★ | 下游全靠它定錨（比例/範本/文案結構）；但可秒選/AI 推論，不拖慢 |
| `create` | ❌ | ❌ | ★ | 沒有素材就沒有貼文；系統必經產出步 |
| `complete` | ❌ | ❌ | ★ | 完成/發佈是旅程終點；內含**品牌鎖＋來源＋成本**三道強制閘門 |
| `brief` `collect` `edit` `compose` `external` `revise` | ✅ 可刪 | ✅ 可停用 | ○ 可選 | 依案調整；停用不影響安全閘門 |

**閘門恆在（即使刪了對應步）**：
- 刪掉 `external` 步 → 仍可在 `create`/`edit` 內用站內工具；要外部往返時閘門照走。
- 刪掉顯式「品牌」編輯動線 → **發佈前的品牌鎖閘門仍強制**（`complete` 內，品牌未鎖 BLOCK）。
- 任何生成動作 → **成本確認門恆在**（不因刪 `create` 外的步而免）。
- 任何上傳/外部素材 → **來源確認 HOLD 恆在**。

> 一句話：**你能裁掉「引導你走的路」，但裁不掉「安全的門」。**

## 7. 與非線性入口相容（不破壞既有跳關）

可設定工作流**疊加**在既有非線性入口之上，不取代：

| 入口 | 與範本的關係 |
|---|---|
| **意圖玄關（GuidedJourney）** | 依**當前啟用範本**的步驟產生引導；停用步不出現在引導 |
| **`Ctrl+K` 跳關 → `/social/studio`** | 照樣直達；跳過引導列，但**該步的閘門仍在**（如直接出圖仍過成本門） |
| **`WorkflowBar` 點任一步跳入** | 同 `/video` `StageBar`：可點跳；跳到的步若 `dependsOn` 未滿足 → 出「補齊精靈」列缺項（回頭引導／就地快速補） |
| **繼續上次（draft）** | 跳到該貼文停留步；以該貼文**當時綁定的範本**呈現（範本版本 pin，改範本不溯及既往） |
| **熟手停用引導** | 個人化可「精簡模式」：`WorkflowBar` 收起，只靠 `Ctrl+K`＋閘門；範本仍決定必經步 |

**規則**：
- **停用步＝引導列不顯示＋`next` 略過**；但若某動作觸發其閘門，閘門照常（閘門不靠步存在）。
- **必經步＝不可被 `next`/跳關繞過其閘門**：例如 `complete` 的品牌鎖，跳到發佈仍 BLOCK 直到鎖定。
- **範本切換不影響進行中的貼文**：已綁定範本版本的 draft 沿用舊版（`pinnedVersion`），避免中途換範本打亂。

## 9. route / procedure（對回真實；無對應者標待補）

| 動作 | 真實 procedure / 落點 | 狀態 |
|---|---|---|
| 列範本 | `social.listWorkflowTemplates` | **待補（屬資料模型，歸後端）**；先例＝`director.listSessions`/`templates` |
| 讀範本 | `social.getWorkflowTemplate` | **待補**；先例＝`director.loadSession` |
| 存/另存範本 | `social.saveWorkflowTemplate`（→ `workflow_templates` ＋ steps JSON） | **待補（table 待建）**；先例＝`director.saveSession` |
| 刪範本（軟刪） | `social.deleteWorkflowTemplate` | **待補**；先例＝`director.deleteSession` |
