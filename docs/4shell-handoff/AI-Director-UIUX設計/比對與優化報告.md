# 比對與優化報告 — 4-shell restructure（PR #852）

> 分支：`feat/4-shell-restructure`　base：`8b3fbcfa`
> 範圍：用 GitNexus（退用 ripgrep + 強型別編譯驗證）對程式碼做知識圖譜分析，與三份開發計畫深度比對，
> 並實作**安全、非破壞、flag-gated 的前端優化**。
> 硬底線（已遵守）：只推 branch、不合併、不碰 main、**不開 `ENABLE_4SHELL`**、**不動 `server/` 與 `drizzle/`**。

---

## 0. 一句話結論

P0/P6 的 4-shell 接線**比預期乾淨**：54 條既有 route 零遺失、所有面板與 adapter 的 tRPC 呼叫在強型別 client 下**編譯全綠**（無壞掉的 procedure 引用、無簽章不符）。真正可優化的是**前端狀態完整性與無障礙一致性**——本次補上之，其餘缺口屬後端 P3/P4 或需 Bruce 決策，**只列出、不擅自執行**。

---

## 1. 比對方法與工具現況

| 項目 | 結果 |
|---|---|
| GitNexus MCP（`.mcp.json` 的 `gitnexus`） | ❌ server 未註冊；`npx gitnexus@latest` 取套件時 npm-cache 故障（`Cannot destructure property 'package' of 'node.target'`） |
| 退用方案 | ripgrep 靜態掃描 + `tsc --noEmit`（強型別 `createTRPCClient<AppRouter>`）逐項驗證連線 |
| router 表面萃取 | `server/routers.ts`（~9600 行 appRouter）+ `server/routers/*` + `server/subsystems/*` |
| 對照文件 | `AI-Director_開發計畫.md`、`AI-Director_四大系統架構.md`、`director.today_登入後內部盤點.md` |

> 強型別 client 讓「編譯通過」等價於「procedure 路徑、query/mutation、input 形狀皆正確」，因此這份比對的連線正確性**有編譯器背書**，非人工臆測。

## 2. 比對發現（計畫 vs branch 現況）

### 2.1 ✅ 對齊良好（無需動作）

- **零路由遺失**：App.tsx 54 條 Route 一條不動；21 條 `LEGACY_REDIRECTS.from` 全部命中真實既有 Route，`to` 全部命中宣告過的 canonical（舊連結不 404）。
- **面板接線全部真實**：learn 6 面板 + settings 9 分頁的 tRPC 呼叫，全部解析到 server 真實 procedure（見對照表 §F）。
- **adapter 接縫全部真實**：`adapters/*.trpc.ts` 的 `director/commander/generate/contextPacket/orbProxy/vault/creativeProject` 呼叫全部編譯通過。
- **嚴格加法守住**：所有 shell/panel 檔皆未 import `server/`、`drizzle/`、`@shared/schema`（scan 證明）。
- **旗標預設 OFF**：`ENABLE_4SHELL=false` → ShellRoutes() 回 `[]`，行為 == 線上現狀（route-parity 測試證明）。

### 2.2 ⚠ 本次已修的前端缺口（見 §3）

- **錯誤狀態缺失**：13 個有查詢的面板中，**10 個沒有任何錯誤狀態**。因面板用 `retry:false`，查詢一失敗就**靜默落入空狀態**，把「讀取失敗」誤報成「沒有資料」，且無重試出口。
- **狀態元件不一致**：各面板手刻 skeleton/空狀態，文案與結構各異（3 個面板有錯誤態、10 個沒有）。
- **a11y 不足**：載入/錯誤區塊無 `role`/`aria-busy`/`aria-live`，裝飾性 icon 未 `aria-hidden`。

## 3. 本次實作的優化（安全、非破壞、flag-gated）

**原則**：純前端、純加法；只在 `ENABLE_4SHELL`=ON 掛載的 shell 內生效；不碰 `server/`、`drizzle/`、不改 schema、不改任何既有 procedure 呼叫字串（scan 仍全綠）。

### 3.1 新增共用三態元件
`client/src/shells/_shared/PanelState.tsx` — `PanelLoading` / `PanelEmpty` / `PanelError`：
- 載入：`role="status"` + `aria-busy` + `sr-only` 文案。
- 空：`role="status"`、中性提示、裝飾 icon `aria-hidden`。
- 錯誤：`role="alert"` + 可選「重試」（接 tRPC `refetch()`），有 `compact` 行內版維持原版面。
- 只 import 既有 `@/components/ui/*` 與 lucide，**不碰後端**。

### 3.2 為 10 個面板補齊錯誤狀態（查詢失敗→明確錯誤+重試，不再偽裝成空）

| 檔 | 修補的查詢 |
|---|---|
| `learn/panels/NewsPanel.tsx` | `news.list` |
| `learn/panels/CreditsUsagePanel.tsx` | `dashboard.myUsageLogs` |
| `learn/panels/ApiKeysPanel.tsx` | `admin.apiKeysStatus` |
| `learn/panels/LearnDocsPanel.tsx` | `learnHub.list`（保留 fallback，但加錯誤提示透明化） |
| `settings/panels/ObservabilityPanel.tsx` | `admin.allBackgroundJobs` |
| `settings/panels/AgentPrefsPanel.tsx` | `agentPreferences.getRecentActivity`（+ 載入 `role="status"`） |
| `settings/admin/AuditTab.tsx` | `admin.usageLogs` · `admin.apiKeysStatus` |
| `settings/admin/ContentTab.tsx` | `aiModels.list`/`news.list`/`learnHub.categories`（彙總錯誤橫幅） |
| `settings/admin/DataRepairTab.tsx` | `admin.allBackgroundJobs` |
| `settings/admin/FeatureFlagsTab.tsx` | `settings.get` |

> 既有已正確處理錯誤的 3 個面板（`AIModelHubPanel`、`UsersCreditsTab`、`GeneralSettingsPanel`）**未動**，避免無謂改動。

### 3.3 驗收（每步皆綠）
- `npx tsc --noEmit` → **exit 0**
- `scan-shell-routes` / `scan-learn-wiring` / `scan-settings-wiring` → **全綠**
- 單元測試：shell/route 相關測試全過；全庫既有 **31 筆失敗為分支既有**（server 端需 API 金鑰/網路的測試，如 `modelResearcher.test.ts` 等），已用 `git stash` 對 clean HEAD 驗證**本次改動零新增失敗**。
- 變更量：10 檔 +55/−11，外加 1 個新元件檔（surgical diff）。

### 3.5 提示詞庫接線修正（用既有 procedure 安全接上）

對照計畫需求「**生成素材後，把 prompt＋素材一起存進提示詞庫並可重複利用**」深掘 prompt library 後，發現一個 **`tsc` 抓不到的真實接線錯誤** 並修正：

- **缺口**：`client/src/spine/projectGateway.ts › createPromptBlock` 送 `{projectId, label, content}` 給 `promptLibrary.create`，但該 procedure 真實輸入是 `{title(必填), content(必填), …}`。`title` 缺失 → 伺服器 zod 退回；spine 的 optimistic `catch` 把錯誤吞掉（gateway client 為 `as any`，故編譯期無法察覺）。結果：video shell 的「存入提示詞庫」按鈕**靜默失敗、實際沒寫入庫**。
- **修正**：改送 `{title: label, content: text}`，對齊 `PromptLibraryPage` 既有正確呼叫。自此 prompt **真的**寫入 `prompt_library`。
- **安全性**：純前端、零後端改動；僅在 ENABLE_4SHELL=ON 的 video shell spine 生效；預設 mock 路徑不受影響；對既有「會過」的行為零回歸（原本就是失敗，修後變成功）。
- 驗收：`tsc` 綠、三 scan 綠、`client/src/spine` + `client/src/shells` 測試 13 passed。

> 計畫需求達成度：**儲存 + 列出/搜尋/篩選 + 重用** 皆有既有 procedure 可接（見對照表 §G.3）；唯獨 **「prompt ↔ 素材關聯」** 因資料模型無外鍵/中介表而做不到（見 §7 第 10 項，屬後端）。

### 3.4 刻意**不做**（避免風險）
- **型別收斂**：面板多處 `const x: any = q.data ?? {}` 是分支刻意的「鬆綁 tRPC 邊界」慣例（程式碼註解明載）。強行收斂風險高、回報低，列為**後續建議**而非本次動作。
- **載入骨架統一**：保留各面板既有 skeleton 版面（避免 layout 回歸），統一只施於空/錯誤態（缺口與正確性所在）。
