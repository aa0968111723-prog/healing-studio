## §0. 一句話 + 三條最高紅線

**一句話**：開源只能**服務、嵌入「既定計畫的明確缺口」**，藏在五接縫 adapter 之後、用 feature flag 漸進掛上；**不得改變任何已定核心決策或方向**。

**三條最高紅線（違反即 ⚠️ 偏離計畫、預設不採用）：**

1. **不改方向**：候選必須相容 §1 全部鎖定決策。任何會替換技術棧/DB/部署/LLM/Auth/架構方向者，一律標 `⚠️ 偏離計畫—僅供 Bruce 參考、預設不採用`，**不得列為推薦**。
2. **不自動安裝**：本協議所有產物都是**紙上評估**。**禁止** `npm install`／改 `package.json`／改 lockfile／加 submodule／執行任何安裝指令。採用與否由 Bruce 決定，安裝動作由 Bruce 或 Claude 在 Bruce 拍板後執行。
3. **必審授權與供應鏈**：每個候選都要過 §9 的「授權合規 + 供應鏈安全」雙審；沒過不得進推薦。

## §1. 鎖定決策紅線（每個候選都要逐條相容；牴觸＝偏離計畫）

> 下表是**不可推翻的既定決策**。回報每個候選時，必須在「相容鎖定決策」欄逐條對照。**候選只能落在這些決策「之內」當零件，不能要求改變它們。**

| # | 維度 | 鎖定決策（不可改） | 對候選的意義 |
|---|---|---|---|
| L1 | 前端框架 | **React 19 + Vite 7 + Wouter（路由）** | 必須是 React/Vite 生態；**不可**提議 Next.js / React-Router / TanStack Router / Vue/Svelte 取代 |
| L2 | API 層 | **tRPC v11**（+ superjson） | 端到端型別走 tRPC；**不可**提議 GraphQL / ts-rest / REST-codegen 取代 |
| L3 | ORM | **Drizzle ORM** | schema/查詢走 Drizzle；**不可**提議 Prisma / Kysely / TypeORM 取代（Drizzle 生態輔助 OK） |
| L4 | DB 方向 | **Supabase Postgres + pgvector（halfvec(3072) + HNSW）** | 向量留在同一個 Postgres；**不可**提議 Qdrant/Weaviate/Milvus/Pinecone-長存 等外部向量庫取代 pgvector（同在 PG 的補強 OK） |
| L5 | 部署 | **Railway（Dockerfile, /api/health）** | 必須能在 Railway/Docker 跑或被呼叫；**不可**要求換 Vercel/K8s/Serverless-only 平台 |

| L12 | 上線方式 | **flag-gated 漸進（`ENABLE_4SHELL` 等，預設 OFF，OFF==main）；strangler-fig 只加不刪** | 候選功能必須能掛 flag、預設 OFF、可即時回退；不可要求「大爆炸」式替換既有流程 |
| L13 | 認證 | **維持自建 JWT（jose + Google OAuth + TOTP）** | **Auth 框架一律 ⚠️ 偏離計畫**（Supabase Auth/Lucia/Auth.js/Better-Auth 等）；RBAC/權限「授權」層的輔助庫可相容（不碰登入/簽發） |

## §2. 選型準則（七維評分，全部要寫）

每個候選依下列七維評估（對應 `GitHub初篩清單.md` 的欄位）：

1. **缺口對位**：填補計畫的**哪個已知缺口**？（如 M3 video session/segment 狀態機、線上任務 50% 失敗的可靠性三件套、Pinecone→pgvector、`PostingProvider`→社群發佈…）對不上既有缺口的，不收。
2. **里程碑/組件對位**：對映 **P0–P6 / M0–M6 / 五接縫 / 哪個 shell 或脊椎模組**。
3. **鎖定決策相容**：逐條對 §1（L1–L15）打勾或標牴觸。**任何牴觸 → ⚠️ 偏離計畫**。
4. **棧契合度**：語言/runtime（TS/Node ≥20、瀏覽器、Postgres 擴充…）、是否 ESM、是否與 React19/Vite7/tRPC/Drizzle 同生態。
5. **整合工作量**：估 `S/M/L`（S＝接 adapter 一兩天；M＝一個 PR 週期；L＝跨多 PR/需新基礎設施）。寫清楚**接哪條接縫、改哪些檔（對 owner）、要不要新基礎設施（Redis/ClickHouse…）**。
6. **健康度**：stars、最後活躍（以 **2026-06-06** 為基準）、release 節奏、維護者數、open issue 比、是否 archived。**近 12 個月無 commit／已 archived ＝ 健康度紅旗**。
7. **風險（維護/安全/授權）**：見 §9。授權與供應鏈是**否決項**。

**契合度結論**用三級：

- **✅ 推薦**：對位明確缺口、相容全部鎖定決策、授權與供應鏈乾淨、健康度佳、工作量可控。
- **◑ 條件式**：方向相容但有但書（授權 copyleft 需用「服務/連接器」而非 vendor、需新基礎設施、功能成熟度待觀察、僅作參考實作…）。**但書要寫死**。
- **⚠️ 偏離計畫—僅供 Bruce 參考、預設不採用**：牴觸 §1 任一鎖定決策或會改變方向。**列在獨立分區，不混進推薦**。

## §8. 收斂流程（intake → Bruce 拍板，七步）

```
1. 提報    代理用 §4 範本貼 COORDINATION.md §10（自己的子區塊）
2. 初篩    Claude 對 §1 鎖定決策 + §2 七維 + §9 雙審 過濾；牴觸者降 ⚠️ 分區
3. 去重    同缺口多候選 → 收斂成 1 主 + N 備選（寫清楚為何主/備）
4. 落清單  通過者寫進 GitHub初篩清單.md 對應類別（Claude 合併）
5. 授權+供應鏈審  §9 雙審；🔶/❌ 標清楚；copyleft 一律「用服務/連接器、不 vendor」
6. Bruce 拍板  Claude 整理「推薦短名單 + 風險 + 工作量」給 Bruce；採用與否 Bruce 決定
7. 落地    Bruce 拍板後才安裝；一律 adapter 化 + 掛 flag(預設 OFF) + 介面契約測試 + DoD 三件套綠
```

> **收斂偏好**：能用**已在棧內**的東西（Drizzle/zod/tRPC/TanStack/xstate/three/@xyflow…）就不引新依賴；新依賴**愈接近 Postgres/Node 原生、愈少新基礎設施**愈優先（例：Postgres-native 佇列 > 需 Redis 的佇列）。

## §9. 安全護欄（硬規則，三條全程不變）

### 9.1 授權合規必審（否決項）

| 授權類型 | 處置 |
|---|---|
| **寬鬆**（MIT / Apache-2.0 / BSD / ISC / PostgreSQL License） | ✅ 可直接評估採用（仍要保留 NOTICE/歸屬） |
| **弱 copyleft**（MPL-2.0 / LGPL） | ◑ 檔案級 copyleft，可用但**隔離邊界要寫清楚**（不改其原始檔即可） |
| **強 copyleft**（**AGPL-3.0 / GPL**） | 🔶 **不可 vendor 進專有前後端**；只能當**獨立服務/連接器**呼叫（例：Postiz 用 API/MCP、ParadeDB 當外部 PG 擴充服務），且需 Bruce 確認商業合規 |
| **自訂/來源可見授權**（tldraw 自訂、Remotion 商用、SSPL、BSL/Elastic 等） | 🔶 **逐案讀條款**：是否需付費、是否需浮水印、員工數門檻、是否限制 SaaS；標清楚成本，預設不採用直到 Bruce 確認 |
| **無授權檔 / NOASSERTION** | ❌ 視同保留全部權利，不可用，除非作者澄清 |

**審查動作**：讀 repo `LICENSE`＋`package.json` license 欄＋官網定價頁；**copyleft/自訂/商用一律標 🔶 並寫「為何仍相容（當服務）或為何降 ⚠️」**。

### 9.2 供應鏈安全必審（否決項）

- **健康度**：近 12 月有 commit、release 規律、≥2 維護者佳、open-issue 比不離譜、未 archived。單一維護者/低活躍 → 🧪 標旗標 + 評估「可 fork 自維護?」。
- **體積與依賴面**：偏好小依賴面；警惕拉進大量 transitive deps、postinstall 腳本、native binary。
- **完整性**：採用時鎖版本（pin + lockfile + 完整性雜湊）；避免 `latest`。
- **執行面**：評估是否需要在伺服器執行不受信任輸入（生成/上傳/MCP）→ 標安全注意（sandbox、schema 嚴格解析、prompt-injection）。
